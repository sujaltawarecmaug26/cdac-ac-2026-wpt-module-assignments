PART A — WRITTEN QUESTIONS

1. When someone opens my portfolio link, the browser sends an HTTP request to the web server. The server finds the requested HTML, CSS and image files and sends them back. The browser reads the HTML, downloads the linked CSS/images and displays the page. If the site later needs dynamic data, application logic runs on the server and talks to a database; the database stores that data. For this static assignment, the browser displays files served by the web server and no database is needed.

 See client-server-diagram.png for the diagram.

2. I would use POST because a contact message is data being submitted to the server. GET is intended mainly for requesting data and can put form values in the URL. If method is omitted, a form uses GET by default. A successful request commonly returns a 2xx status such as 200 OK or 201 Created. A server-side failure is in the 5xx status-code family.

3. The three types are inline CSS (inside an element's style attribute), internal CSS (inside a style element in the page head), and external CSS (in a separate .css file linked to the page). When declarations compete for the same property, specificity and importance matter; inline styles normally beat ordinary internal and external rules. I would use external CSS for four pages because one shared file keeps the look consistent and is easier to maintain.

4. The #intro rule applies because an ID selector has the highest specificity among the listed selectors. From strongest to weakest: #intro (ID), .note (class), p (element), * (universal selector). If declarations have equal specificity, the later applicable rule generally wins.

5. Margin is the space outside an element's border; padding is the space between its content and border.

        margin
      ┌──────────────────────────┐
      │  border                  │
      │  ┌────────────────────┐  │
      │  │ padding            │  │
      │  │  ┌──────────────┐  │  │
      │  │  │ content      │  │  │
      │  │  └──────────────┘  │  │
      │  └────────────────────┘  │
      └──────────────────────────┘

   With box-sizing: border-box, the declared width and height include the content, padding and border, making sizing easier to control.

6. JavaScript runs in an environment such as a browser, where a JavaScript engine (for example, V8 in Chrome) parses and executes it. Modern engines interpret and compile code internally, so a developer usually does not need to compile it manually. JavaScript can validate a form before submission and update page content after a button click; HTML and CSS alone cannot provide that general behaviour.

7. JavaScript is dynamically typed, so a variable can hold different types of values. With `a = 5`, a receives a number; after `a = "hello"`, it holds a string. In modern code I would declare it with `let` or `const`. Three basic types are number, string and boolean.

8. `static` is the normal document flow and is the default. `relative` keeps an element in its normal place but allows it to be offset. `absolute` positions an element relative to its nearest positioned ancestor. `fixed` positions it relative to the browser window and it stays in place while scrolling. `top`, `right`, `bottom` and `left` set the offset from the relevant edges for positioned elements.

9. With flex values 1, 2 and 1, the boxes share the available free width in a 1:2:1 ratio: approximately 25%, 50% and 25% (before accounting for gaps, padding and borders). `gap` adds space between flex items. `justify-content: center` groups the items toward the centre along the main axis.
